# 应急处置 Checklist（蓝队 playbook）

> 适用于：CTF 攻防赛（AWD）、靶场演练、授权环境下的真实入侵响应。
> 按顺序执行，每步打勾，不要跳步。

## 阶段一：确认与止损（0–30 分钟）

- [ ] 确认事件真实性（告警复核，排除误报/扫描器噪音）
- [ ] 定级：影响范围（单点/横向）、数据敏感性、是否持续中
- [ ] 保全证据：日志/内存/磁盘快照先拷贝再操作（`defense/log_analyzer.py` 跑基线扫描）
- [ ] 止损隔离：受影响主机断网不断电（保内存证据）；或 ACL 封禁攻击源
- [ ] 通知相关人员，建立响应频道与记录文档（所有操作留痕）

## 阶段二：排查与定位（30 分钟–4 小时）

- [ ] 攻击时间线还原：首失陷时间点、入口向量、横向路径
- [ ] 查持久化：计划任务、自启项、后门账户、webshell、异常 SSH key
- [ ] 查窃取：外传流量、异常大文件读取、数据库导出痕迹
- [ ] 确定根因：按 `vuln_root_cause.md` 五类归因
- [ ] 评估影响面：凭据是否泄露（全部轮换）、哪些数据被触达

## 阶段三：清除与恢复（4–24 小时）

- [ ] 清除后门与恶意文件（每个都要有清单，逐一核销）
- [ ] 修复漏洞根因（按 `remediation.md` 模板出修复并回归验证）
- [ ] 轮换全部可能暴露的凭据/密钥/token
- [ ] 从干净备份恢复受影响系统；无法确认干净则重装
- [ ] 恢复业务，灰度上线并加强监控

## 阶段四：复盘与加固（1 周内）

- [ ] 输出事件报告：时间线、根因、损失、处置动作、教训
- [ ] 同类问题全环境排查（一套漏洞，处处检查）
- [ ] 补充检测规则：本次攻击特征写入 IOC 规则库
- [ ] 归档进错题/题库（learning/replay.py），纳入训练回放
- [ ] 更新应急预案与值班手册

## AWD 赛制特化要点

- 开局先备份全部服务源码与数据（被植马后可对比）
- 自动化巡检脚本常驻：webshell 扫描、异常进程、流量异常
- 补丁最小化：只修漏洞点，不动业务逻辑，防自杀式补丁
