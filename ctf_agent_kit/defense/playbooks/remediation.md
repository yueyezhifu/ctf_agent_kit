# 修复建议模板（蓝队 playbook）

> 原则：每条修复建议必须可执行、可验证、带优先级。

## 优先级定义

| 级别 | 含义 | 时限 |
|---|---|---|
| P0 | 正在被利用 / 可直接 RCE | 立即（热修/WAF 规则先挡） |
| P1 | 可未授权访问敏感数据 | 24h |
| P2 | 需一定条件的利用 | 1 周 |
| P3 | 加固项 | 迭代内 |

## 分漏洞类型修复模板

### SQL 注入
- 正解：参数化查询/ORM 绑定变量；禁止字符串拼接 SQL
- 辅助：最小权限数据库账户、WAF 规则兜底、错误信息不外显
- 验证：payload 回归测试 `' OR 1=1-- ` 等全量打一遍

### 文件上传
- 正解：白名单扩展名 + 内容嗅探 + 重命名存储 + 存储目录禁执行
- 辅助：独立静态资源域、CDN 隔离
- 验证：上传 .php/.jsp/.svg 等全被拒

### 命令注入
- 正解：禁用 shell 拼接，用参数数组调 exec；必须拼接时用白名单转义
- 验证：fuzz 元字符 `;&| $\`` 无执行副作用

### 反序列化
- 正解：换 JSON 等无代码执行能力的格式；必须用时做类白名单
- 辅助：升级组件到无 gadget 版本

### 越权/IDOR
- 正解：服务端逐请求鉴权（对象级权限校验），不信任客户端传的 id
- 验证：横向/纵向越权用例回归

### SSRF
- 正解：出网白名单（域名级）+ 禁内网段 + 禁用危险协议（gopher/file）
- 验证：内网 IP/127.0.0.1/元数据地址全部不可达

## 修复闭环

1. 修复提交 → 2. 安全回归测试（原始 PoC 必须失效）→ 3. 同类模式全局排查 → 4. 上线观察 72h 告警 → 5. 归档进错题库（learning/replay）
